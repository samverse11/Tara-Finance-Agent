# Tara Finance Agent — Design

## Architecture

```
User → POST /ask → Tara Agent (LLM) → Tool selection → PostgreSQL → Structured results → Answer
```

The LLM never performs calculations. It interprets questions, selects tools, and explains SQL-backed results.

## Database

| Table | Purpose |
|-------|---------|
| `transactions` | Bank spends with `merchant` + `merchant_canonical` |
| `funds` | Fund metadata |
| `fund_nav` | Daily NAV (separate table for date-range queries) |
| `holdings` | User positions (`id` generated by DB) |
| `request_logs` | Observability for `/ask` |

### Merchant canonicalization

At ingest time, all merchant strings in a dataset are normalized (uppercase, collapsed whitespace). The shortest token-prefix match becomes `merchant_canonical` (e.g. `SWIGGY ORDER` → `SWIGGY`). No hardcoded merchant list.

### Business rules (enforced in SQL)

- **Transfers**: `category = transfer` excluded from spending unless `includeTransfers` is set.
- **Refunds**: negative `amount` values reduce `SUM(amount)` naturally.

## Tools (3)

1. **query_transactions** — spending, merchants, categories, monthly breakdowns, top merchants, biggest expense.
2. **query_portfolio** — portfolio value, realised return, period return, fund lookup/comparison.
3. **detect_recurring** — subscription-like patterns from transaction intervals.

### Financial definitions

- **Period return**: `(endNAV - startNAV) / startNAV * 100` — fund performance between dates.
- **Realised return**: `(currentValue - purchaseCost) / purchaseCost * 100` — user-specific gain.

## Ingestion

```bash
npm run ingest              # sample_a/
npm run ingest sample_b     # specific folder
npm run ingest:all          # all sample_* present
```

Per sample folder (`transactions.json`, `funds.json`, `holdings.json`):

1. Delete prior rows for that `source_file`
2. Insert transactions with canonical merchants
3. Upsert funds + NAV (`fund.nav`, not `nav_history`)
4. Insert holdings (no JSON `id`)

## Observability

Each `/ask` request logs `question`, `tools_called`, `status`, `latency_ms`, `answer` to `request_logs`.
